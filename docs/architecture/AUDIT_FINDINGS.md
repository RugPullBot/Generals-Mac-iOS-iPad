# GeneralsX / Zero Hour — Prioritised Defect Report (93 verified findings)

Scope note: priority is real-world impact on a **shipping iPad build**. Crashes and silent corruption on paths a player actually walks (map load, texture load, INI load, save/load, in-game draw/logic) outrank network/GameSpy paths, which in turn outrank dev tooling and cosmetics. Several verifier notes trimmed the impact of findings that survived on mechanism alone — those are flagged inline and collected at the end.

## 1. Memory safety

### 1.1 `W3DRoadBuffer::loadFloat4PtSection` bounds vertex writes with the *index* limit — 36 KB stack smash
`GeneralsMD/.../W3DDevice/GameClient/W3DRoadBuffer.cpp:703` (and `:725`)
`vb[MAX_SEG_VERTEX]` is 500 entries (12 000 B) but both guards compare against `MAX_SEG_INDEX` (2000). A road segment >~2500 world units over uneven terrain writes `vb[500..1999]` — up to 36 000 bytes past a stack array, over `ib[]`, three `TColumn` structs, saved registers and the return address. Fires at **map load**, driven by untrusted community/multiplayer map data. Secondary: `ib[2000]` has no slack and the guard at `:733` is followed by six writes, so index 1998 writes `ib[1998..2003]`.
**Fix:** `MAX_SEG_VERTEX` at 703 and 725; declare `ib[MAX_SEG_INDEX+4]` (matching `allocateRoadBuffers`) or tighten 733 to `numRoadIndices+6 > MAX_SEG_INDEX`.

### 1.2 Map decompression allocates from one file field and writes from another
`GeneralsMD/.../Common/System/DataChunk.cpp:73`
`CachedFileInputStream::open` sizes the destination from wrapper bytes 4–7, then `REF_decode`/`BTREE_decode`/`HUFF_decode` **discard `destLen` entirely** (`CompressionManager.cpp:283-309`) and write until the RefPack stream's own EOF opcode. ~257:1 expansion is reachable. A `.map` with `"EAR\0"` + `uncompLen=16` and a 4 MB payload overwrites 4 MB of heap. Runs during MapCache enumeration — i.e. on every launch, over files the user never chose to load, including peer-transferred maps.
**Fix:** clamp `uncompLen` (reject `<=0` and above a ceiling) before `NEW`, and thread a real destination bound into the three EAC decoders. Note: cross-checking RefPack's internal `ulen` is *not* sufficient — that value is never used to bound the write.

### 1.3 Targa palette load writes at a file-controlled offset into a 1 KB stack array
`Core/Libraries/Source/WWVegas/WWLib/TARGA.cpp:382`
`palette += CMapStart * depth; File_Read(palette, CMapLength * depth)` with no validation of `CMapStart` (signed short, can be negative), `CMapLength` or `CMapDepth`. All three in-engine callers pass `char palette[256*4]` — exactly full at 256×32bpp, so *any* nonzero `CMapStart` already overruns. Attacker chooses offset and length. Live path: paletted TGAs are accepted (`ww3dformat.cpp:288`).
**Fix:** reject unless `CMapStart >= 0 && CMapLength > 0 && CMapDepth <= 32 && (CMapStart+CMapLength)*(CMapDepth>>3) <= palette_size`; pass `sizeof(palette)` from the three WW3D2 callers.

### 1.4 Targa RLE decode has no destination bound and underflows its pixel counter
`Core/Libraries/Source/WWVegas/WWLib/TARGA.cpp:1130`
`pixel_count -= count` with unsigned `pixel_count` and no `count <= pixel_count` check: an over-long final packet wraps to ~2^64 and the loop keeps decoding file bytes into the heap until a read fails. Up to 512 B per packet, unbounded in total.
**Fix:** reject `count > remaining` with `TGAERR_SYNTAX`, and bound `image` against `mImage + W*H*depth`.

### 1.5 BlendTileData parse uses map-file fields as array bases and loop bounds *(merged)*
`Core/GameEngineDevice/.../W3DDevice/GameClient/WorldHeightMap.cpp:1025` and `:1160`
`firstTile` is used unvalidated as the base for `readTiles(pStr, m_sourceTiles + firstTile, width)` — up to 100 pointer slots plus 16 KB of pixel data per tile at an attacker-chosen offset into a 1024-entry array (and again at `:1126`, `:1499`, `:1563`). Separately `m_numCliffInfo` (no check at all, 42 B/iter into a 32384-entry array), `m_numEdgeTextureClasses` (no check), `m_numTextureClasses` and `m_numBlendedTiles` (DEBUG_ASSERTCRASH only) drive write loops. `W3DTreeBuffer.cpp:493` guards the identical call; this path does not.
**Fix:** validate every count immediately after `readInt()` against its array constant and `throw ERROR_CORRUPT_FILE_FORMAT` (the function already throws at `:1043`/`:1156`); range-check `firstTile + width*width <= NUM_SOURCE_TILES`.

### 1.6 Unknown `DamageType` name yields −1, used directly as an array index
`GeneralsMD/.../Common/DamageFX.cpp:167`
`getSingleBitFromName` returns −1 for an unrecognised token; `DamageType` is signed, so all four consumers run one iteration at `dt == -1`, writing 128 bytes *before* a hash-map node (allocator metadata / previous block). Same pattern at `Armor.cpp:99` (4-byte OOB write) and `INI.cpp:1969/1975`. Trigger: a typo, or a `#if RTS_GENERALS`-only token in a Zero Hour DamageFX block. The veterancy half of the same function throws correctly.
**Fix:** validate the bit index before the cast; `throw INI_INVALID_DATA` on out-of-range. Audit all `getSingleBitFromName` call sites.

### 1.7 `obfuscate()` self-modifying XOR overflows a password-sized heap buffer
`GeneralsMD/.../Menus/WOLLoginMenu.cpp:126`
`*c = *c++ ^ *c2++;` — under C++20 (set project-wide at `config-build.cmake:75`) the RHS is sequenced first, so the store lands on `buf[i+1]`, destroying the terminator the loop is about to test. Verified empirically with Apple clang 17 at `-std=c++20`: reaches index 401 on an 8-byte allocation; guard-page test faults at index 8. Fires on the **first** successful login (`write()` at `:217`) and on every later launch that loads a saved `pass_<email>`.
**Fix:** `*c = *c ^ *c2; ++c; ++c2;` — this also restores the self-inverse property the code silently lost.

### 1.8 `GLM_GET_SELECTION` writes 4 bytes into an 8-byte pointer *(merged)*
`Core/GameEngine/Source/GameClient/GUI/Gadget/GadgetListBox.cpp:1798`; victims at `WOLLobbyMenu.cpp:503` and `GameSpy/Chat.cpp:154`
`*(Int*)mData2 = static_cast<Int>(reinterpret_cast<intptr_t>(list->selections));` — `Int` is `int32_t`. Callers declare an uninitialized `Int *selections;` and pass `&selections`; the upper 32 bits keep stack garbage, and arm64 heap addresses always have nonzero high bits, so the reconstructed pointer is **deterministically** wrong. Then dereferenced. Both branches of the handler are 4-byte writes, so single-select is equally broken. `WOLLobbyMenu.cpp:503` runs on every lobby-list repopulate, before any chat.
**Fix:** change the contract to `Int**` (`*(Int**)mData2 = list->selections;`) and update the two pointer-style call sites; leave the ~30 genuine `Int*` single-select callers alone.

### 1.9 `processPlayerLeave` indexes 8-element arrays with an unvalidated wire byte
`Core/GameEngine/Source/GameNetwork/ConnectionManager.cpp:1090`
`leavingPlayerID` is a separate payload field from the validated sender ID and ranges 0–255. `m_connections[200]` / `m_frameData[200]` are read 1536 bytes past their arrays, and `setQuitting()` / `setQuitFrame()` are called through whatever garbage word is there — an OOB **write** at an attacker-influenced address. Every sibling handler in the file (`processFrameResendRequest`, `processRunAheadMetrics`, `processDisconnectChat`, `disconnectPlayer`) has the guard.
**Fix:** `if (playerID >= MAX_SLOTS) return PLAYERLEAVECODE_UNKNOWN;` after line 1089; move the `m_frameData` null check ahead of the assert at 1094.

### 1.10 `readFileMessage` allocates and copies an unbounded 32-bit length from the packet
`Core/GameEngine/Source/GameNetwork/NetPacket.cpp:1351`
`dataLength` is taken verbatim and used for both `NEW UnsignedByte[dataLength]` and `memcpy` out of a 1094-byte fixed member array. `0xFFFFFFFF` = 4 GiB alloc + 4 GiB read. The adjacent filename read was hardened; the payload length was not. All the `read*` helpers advance `i` with no end-of-buffer awareness.
**Fix:** reject unless `dataLength <= (m_packetLen - i)` and `<= MAX_PACKET_SIZE`. Durable fix: thread the packet length into the `read*` helpers.

### 1.11 LAN wide-string copy reads a fixed count regardless of source length, leaking heap onto the wire
`Core/GameEngine/Source/GameNetwork/LANAPIhandlers.cpp:51`
`for (i = 0; i < len; ++i) dest[i] = src[i];` where `len` is always the **destination** capacity. 14 call sites. Worst: chat, `len=100` × 4-byte `wchar_t` = 400 bytes read from a short `UnicodeString` (or from `&TheNullChr`, a single static char, or a bare `L""` literal). The low 16 bits of each stray word are then UDP-broadcast to the subnet. This is a port regression — it replaced `wcslcpy`.
**Fix:** stop at the source terminator. Also `LANAPIhandlers.cpp:66`: `len > MAX_COMPUTERNAME_LENGTH` should be `>=`, and the scan at `:61` must be bounded by the inbound field size.

### 1.12 Replay string readers write one element past their 1024-entry stack buffers
`GeneralsMD/.../Common/Recorder.cpp:1330` (and `readAsciiString` at `:1356/:1358`)
The bound is tested on the index just *stored*, then `index` is incremented and the new index written without re-testing: `str[1024]` on a 1024-element array, tripping `__stack_chk_fail`. Reached from `readReplayHeader`, which parses every `.rep` in the Replays folder when the list screen opens, after validating only a 6-byte magic.
**Fix:** `while (index + 1 < ARRAY_SIZE(str) && str[index] != 0)`.

### 1.13 `QuotedPrintableToAsciiString`'s bounds counter is never incremented
`GeneralsMD/.../Common/System/QuotedPrintable.cpp:218`
`while (*src && i<1023)` — nothing ever touches `i`. The real cursor `c` is unbounded, so any input over 1023 literal chars walks off `static char dest[1024]`. `UserPreferences::load` reads with `char buf[2048]`, so a ~2000-char value in any prefs file overflows by ~977 bytes. Live feeders include the plain offline `SkirmishPreferences::getPreferredMap`.
**Fix:** index through `dest[i++]` with the existing guard, matching the already-correct `AsciiStringToQuotedPrintable`.

### 1.14 Unbounded `strcpy` of an INI-supplied module name into `char tmp[256]`
`GeneralsMD/.../Common/Thing/ModuleFactory.cpp:604`
`makeDecoratedNameKey` copies an INI token (up to ~1027 bytes — `INI_MAX_CHARS_PER_LINE` is 1028) into a 256-byte stack array. Reachable from any Object INI **and from a `map.ini` bundled with a downloaded/transferred map**. The override-mode rejection happens *after* the overflow.
**Fix:** build the key in an `AsciiString`/`std::string`, or early-out with `NAMEKEY_INVALID` when `name.getLength() >= sizeof(tmp)-1`. Callers already handle not-found.

### 1.15 Tooltip trace `sprintf`s three INI strings into a 512-byte stack buffer
`GeneralsMD/.../GUICallbacks/ControlBarPopupDescription.cpp:237` (also `:302`, `:329`)
Port-added `[GX-ISSUE144]` instrumentation, not wrapped in `RTS_DEBUG`. ~447 bytes of headroom for `getName()` + `getTextLabel()` + `getDescriptionLabel()`, all data-driven and all overridable from a network-transferred `map.ini`. Fires on hover.
**Fix:** delete the instrumentation (nothing reads `log_buffer`); if kept, `snprintf`.

### 1.16 MapCache `numPlayers` indexes an 8-element array, and the reader struct is uninitialized
`GeneralsMD/.../Common/INI/INIMapCache.cpp:195`
`MapMetaDataReader mdr;` has no constructor, so `m_numPlayers` etc. are indeterminate; unknown INI fields only DEBUG_CRASH, so a foreign-written `MapCache.ini` silently leaves it that way. `for (i=0; i<md.m_numPlayers; ++i) md.m_waypoints[...] = mdr.m_waypoints[i];` then reads far past an 8-entry stack array. The *producer* clamps, so only externally authored cache files trigger it — on iOS that file lives in a writable sandbox dir.
**Fix:** `MapMetaDataReader mdr = {};` (it is an aggregate) plus `min(numPlayers, MAX_SLOTS)`, or reject the entry outright.

### 1.17 Multi-select `selections` array is one slot short *(merged)*
`Core/GameEngine/Source/GameClient/GUI/Gadget/GadgetListBox.cpp:1072` and `:223`
Allocated `NEW Int[listLength]` but the format is up to `listLength` indices **plus** a −1 terminator. Selecting the last unselected row writes `selections[listLength]`; the array is then all-non-negative, so the *next* click's `while (selections[i] >= 0)` scans heap until it finds a negative int and writes two Ints there. Independently, `removeSelection`'s `memcpy` count is `(listLength - i)` where it should be `(listLength - i - 1)` — a 4-byte over-read on **every** deselect, unconditionally.
**Fix:** allocate `listLength + 1` (and memset accordingly at `:1379/:1561/:1617/:2445`); use `memmove` with `(listLength - i - 1)`; bound the scan loops with `i < listLength`.

### 1.18 `FlightDeckBehavior::xfer` indexes `m_rampUp[MAX_RUNWAYS]` inside the loop
`GeneralsMD/.../Object/Behavior/FlightDeckBehavior.cpp:1704`
Constant index instead of `i`, one past the end (lands in tail padding, so no cross-object corruption). Functional damage is real: ramp state is never saved or restored, so a carrier saved mid-launch reloads with `m_rampUp[i] == FALSE` but the ramp timers intact — the door sticks in `DOOR_x_OPENING` and the launch is delayed a full `LaunchRampDelay`.
**Fix:** `&m_rampUp[i]`. Same byte count, so no version bump needed.

### 1.19 `AssaultTransportAIUpdate::xfer` loads an unbounded member count
`GeneralsMD/.../AIUpdate/AssaultTransportAIUpdate.cpp:507`
`m_currentMembers` is overwritten from the stream and used as the loop bound into three 10-element arrays; index >10 walks the trailing members (including `m_currentMembers` itself, so the bound becomes stream-controlled mid-loop) and off the pool block. Trigger is a locally corrupt save, so this is hardening rather than a live crash — but `RailedTransportAIUpdate.cpp:395` and `DozerAIUpdate.cpp:2498` establish the project's own convention. Also: `m_newMember[]` is never xfered at all.
**Fix:** `if (m_currentMembers < 0 || m_currentMembers > MAX_TRANSPORT_SLOTS) throw SC_INVALID_DATA;`.

### 1.20 `recordShoreLineSortInfos` dereferences before the bound test
`Core/GameEngineDevice/.../W3DDevice/GameClient/BaseHeightMap.cpp:1520` (and `:1553`)
`while ((m_shoreLineTilePositions[j].m_xy & 0xffff) == x && j < m_numShoreLineTiles)` — `&&` evaluates the load first. Guaranteed once per call (the final run always terminates by reaching `j == N`), and genuinely out of bounds whenever the tile count lands exactly on capacity (4096, 4608, …).
**Fix:** swap the operands.

### 1.21 `DataChunkTableOfContents::read` loops on an unvalidated count left uninitialized on short read
`GeneralsMD/.../Common/System/DataChunk.cpp:555`
`count` and `len` are uninitialized; `CachedFileInputStream::read` returns 0 without touching the buffer at EOF. A 4-byte `.map` containing only `"CkMp"` leaves `count` as stack garbage and the loop allocates that many pooled `Mapping`s — jetsam kill during map enumeration. A crafted `count = 0x7FFFFFFF` reaches the same state deterministically. Runs before any parser is registered, so the existing `ERROR_CORRUPT_FILE_FORMAT` path never gets a chance.
**Fix:** initialize both; check every `read` return; bound `count` by `remainingBytes / 5`.

### 1.22 Preference line without `=` reads past a 1-byte static
`Core/GameEngine/Source/Common/UserPreferences.cpp:137`
`val = line.str() + 1;` assumes `nextToken` stopped at a separator. When it didn't, `line.m_data` is null and `str()` returns `&TheNullChr` — a single static char — so `strlen` runs from one byte past it. Triggers on a blank line, a hand-added comment, a file truncated mid-write (realistic when iOS kills a backgrounded app during `write()`), or any value >2047 bytes split by `fgets`.
**Fix:** `if (line.isEmpty()) continue;` or find `'='` explicitly.

### 1.23 `copyReplay()` builds a destination path from an uninitialized 1024-byte buffer
`GeneralsMD/.../Menus/ReplayMenu.cpp:819`
On non-Windows, `SHGetPathFromIDList` is a stub that returns 0 and writes nothing; both return values are discarded and `newFilename.set(path)` `strlen`s indeterminate stack. Realistic outcome is a garbage path and a generic failure message, not a fault — but it is UB on a user-reachable button.
**Fix:** check the return values, `char path[1024] = ""`, and give Apple a real destination (Documents / `$HOME/Desktop`).

### 1.24 Uninitialized `Coord3D` used as a move goal when a dock bone is missing
`GeneralsMD/.../DockUpdate/RailedTransportDockUpdate.cpp:416`
`getPristineBonePositions` leaves `positions[]` untouched on a miss and its return is discarded; `finalPos` (stack garbage) is transformed and handed to `aiMoveToPosition`. Logic-side, so it desyncs multiplayer/replays if it fires. Requires a model without `DOCKWAITING07`, so latent with stock assets. The base class treats missing dock bones as an expected case everywhere else in the same file.
**Fix:** `finalPos.zero();` and only issue the order when the call returns 1.

### 1.25 Word-wrap look-ahead reads past the string terminator
`Core/Libraries/Source/WWVegas/WW3D2/render2dsentence.cpp:1046` (and `:763`)
`*word+1` parses as `(*word)+1`, so all three hot-key guard clauses are constant-true and the pointer is bumped unconditionally — including onto the NUL. The everyday symptom is a wrong wrap width (`L"Load & Save"` merges two words); the over-read needs a trailing bare `&`. Buffer padding makes a fault unlikely.
**Fix:** `*(word+1)` in both places, and drop the no-op `*` on the increment.

### 1.26 `exePath` wide buffer terminated at index 1023, not at the copy position
`Core/GameEngine/Source/Common/ReplaySimulation.cpp:172`
`command.format(L"\"%s\"...", exePath)` then reads ~960 indeterminate `wchar_t`s. Contained today only because the POSIX `WorkerProcess::startProcess` is a stub — becomes a functional break the moment fork/exec lands.
**Fix:** bound the loop by `ARRAY_SIZE(exePath)-1` and terminate at `i`.

## 2. Debug-only or absent guards (null deref)

### 2.1 Overlord tank/truck deref the lazily-allocated tint envelope; the aircraft variant checks it
`Core/GameEngineDevice/.../Draw/W3DOverlordTankDraw.cpp:89` and `W3DOverlordTruckDraw.cpp:89`
`riderDraw->setColorTintEnvelope(*getDrawable()->getColorTintEnvelope())` — the host's envelope is `nullptr` until it is first tinted, and tint propagation is one-directional (host→rider), so a rider that acquires subdual/EMP/frenzy tint independently while the host never has is a durable state, not a race. Runs **every frame** for any Overlord with a rider. `W3DOverlordAircraftDraw.cpp:100` has exactly the guard.
**Fix:** copy the aircraft guard into both files.

### 2.2 Repeat-command ('Z') branch dereferences a null `lastCommand`; only guard is `DEBUG_CRASH`
`Core/GameEngine/Source/GameNetwork/NetPacket.cpp:729`
No `continue`/`break` after the assert, which is `((void)0)` in release. `commandType` initialises to 0 == `NETCOMMANDTYPE_ACKBOTH`, so a **one-byte** datagram `0x5A` with correct magic + CRC (both computable from this GPL source) reaches `lastCommand->getCommand()`. `doRelay()` runs this on every buffered datagram before any sender validation.
**Fix:** `++i; break;` inside the null branch.

### 2.3 `ConstructNetCommandMsgFromRawData` has no `default:` and writes through a null `msg`
`Core/GameEngine/Source/GameNetwork/NetPacket.cpp:175`
Unhandled command types (12, 13, 21, 29, 30–255) leave `msg == nullptr`, then `msg->setExecutionFrame(frame)` — a store through null. The sibling `getCommandList()` has the check. Caller `NetCommandWrapperList.cpp:203` also derefs the return unchecked, reachable via `numChunks == 0` (`isComplete()` is true immediately) or `totalDataLength == 65536` truncating to 0.

### 2.4 Null `EnumeratedIP` dereferenced; the guard is an empty `if` body
`GeneralsMD/.../Menus/LanLobbyMenu.cpp:439` and `NetworkDirectConnect.cpp:331`

Fresh install (`m_defaultIP == 0`) → tap Multiplayer → Network → EXC_BAD_ACCESS. `OptionsMenu.cpp:1098` shows the correct pattern.

### 2.5 Gadget image-draw funcs deref an unchecked image slot *(merged)*

The repo's own `ExtrasMenu.wnd` has five `HORZSLIDER` blocks with `DISABLEDDRAWDATA` row 0 = `NoImage`, and the macOS deploy script stages that file. Both files contain a dead `...DrawA` variant that *does* guard correctly.
**Fix:** restore `barCenter` to the live condition; add `if (fillSquare == nullptr || blankSquare == nullptr) return;` after slider line 149.

### 2.6 Rank-8 purchase-science loop indexes an empty `ScienceVec`
`GeneralsMD/.../ControlBar/ControlBar.cpp:371`
`st = commandButton->getScienceVec()[0];` with no emptiness check, while the rank-1 and rank-3 loops directly above it check. ### 2.7 Unknown module name yields a null `ModuleData`, dereferenced immediately

### 2.8 `AITNGuardInnerState::update` derefs `m_attackState` without the guard every sibling has
`GeneralsMD/.../AI/AITNGuard.cpp:424` (and `:409`)
`m_attackState` is only created in `onEnter`, which early-returns when the nemesis ID no longer resolves; `loadPostProcess` calls `onEnter` and discards the return, so the machine can sit in `AI_TN_GUARD_INNER` with a null sub-state. ### 2.9 `transferAssetsFromThat` derefs a player template that is null for the neutral player

### 2.10 Unchecked null from `getClosestObject()` dereferenced in the physics update
`GeneralsMD/.../Update/TensileFormationUpdate.cpp:298`
`tree->isKindOf(KINDOF_SHRUBBERY)` on a possibly-null return. `Core/GameEngine/Source/GameClient/LanguageFilter.cpp:90`
`wcsstr(buf, token.str())` restarts at `buf[0]` for every token while the tokenizer advances monotonically. ### 6.22 Maintained-animation frame restore is off by one (precedence)
`Core/GameEngineDevice/.../Draw/W3DModelDraw.cpp:2217`
`prevAnimFraction * Get_Num_Frames()-1` parses as `(f*N)-1`; the forward map divides by `(N-1)`. **Fix:** `prevAnimFraction * (Get_Num_Frames()-1)`.

### 6.24 `ExecuteAnimationFades` is parsed into module data nothing reads

## 7. Logic & correctness — UI / input

### 7.1 `TOGGLE_LOWER_DETAILS` never toggles back and destroys the saved originals
`GeneralsMD/.../MessageStream/CommandXlat.cpp:3300`
`static Bool isLowDetails` is read but never assigned anywhere in the tree. The restore branch is unreachable; every press re-snapshots the already-lowered values over the originals. One press disables shadows/lightmap/cloudmap and clamps particles to 1000; the second press makes it permanent for the session.
**Fix:** toggle the flag at the end of each branch.

### 7.2 Raw double-click messages are not treated as button-downs *(merged)*
`GeneralsMD/.../MessageStream/LookAtXlat.cpp:257/284` and `SelectionXlat.cpp:971`
On SDL3, `MSG_RAW_MOUSE_*_DOUBLE_CLICK` **replaces** the second button-down rather than accompanying it. `CommandXlat.cpp:3861` was explicitly patched for this ("it implicitly is a raw button down event as well"); these two were not.
- LookAtXlat: a rapid second middle press starts no rotation and the whole drag does nothing; a rapid second right press starts no RMB scroll.
- SelectionXlat: the anchor/timestamp stay pinned to the first press, so `isClick` fails on the second release and the right-click deselect / GUI-command cancel / placement cancel is silently swallowed. In a multi-click burst SDL reports `clicks>=2` for every press after the first, so the anchor is pinned for the whole burst.
**Fix:** add the double-click case labels alongside the button-down cases in both files.

### 7.3 Missing `abs()` on `dy` makes the middle-click camera reset unreliable
`GeneralsMD/.../MessageStream/LookAtXlat.cpp:311`
`if (dx<0) dx = -dx;` was copy-pasted for x only, and `PIXEL_OFFSET` is `UnsignedInt`, so a negative `dy` promotes to ~4.29e9 > 5. Result: 5 px of slop downward, **1 px** upward. One pixel of upward trackpad drift silently cancels the camera reset.
**Fix:** add `if (dy<0) dy = -dy;` **and** make `PIXEL_OFFSET` an `Int` — the two halves must land together or a large upward drag starts snapping the camera home.

### 7.4 `GadgetRadioSetSelection` passes the address of `sendMsg`, so `GBM_SELECTED` always fires
`Core/GameEngine/Source/GameClient/GUI/Gadget/GadgetRadioButton.cpp:445`
Sender passes `&sendMsg`; the handler reads `(Bool)mData1` as a value, which is unconditionally true for a stack address. All 34 call sites pass FALSE, i.e. all of them want suppression. Real cost: `MapSelectMenu.cpp:369` fires a spurious `TheMapCache->updateCache()`, a redundant listbox repopulate and a **preferences file write** on every menu entry.
**Fix:** pass the value, not its address.

### 7.5 Tab control's `GWM_LEFT_DOWN` falls through to `default: return MSG_IGNORED`
`Core/GameEngine/Source/GameClient/GUI/Gadget/GadgetTabControl.cpp:117`
Missing `break;`, so the trailing `return MSG_HANDLED` is unreachable and the branch that actually switches panes returns the opposite of the branch that does nothing. The dispatcher then walks the click up the parent chain and, when it exhausts to null, skips the open-combo-box teardown entirely (the report has this consequence inverted). Also leaves `WIN_INPUT_USED` unset. Data-driven — no `.wnd` in this repo instantiates a tab control, so unverified in practice.
**Fix:** add `break;`.

### 7.6 `VIEW_TEAM0` hotkey guard is off by one
`GeneralsMD/.../MessageStream/SelectionXlat.cpp:1243`
`if (group >= 1 && group <= 10)` on a 0-based index; the three sibling handlers all use `>= 0 && < 10`. Group 0 silently does nothing, 1–9 work. No OOB (`getHotkeySquad` range-checks). Needs a hardware keyboard, so it will not manifest under touch.
**Fix:** `group >= 0 && group < 10`.
