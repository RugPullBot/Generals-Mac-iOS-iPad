Two traps found while doing it:

* **`-DSAGE_USE_CCACHE=OFF` is a no-op on an existing build dir.** `cmake/ccache.cmake`'s `else()`
  branch only prints "ccache disabled" — it never unsets the `CMAKE_C/CXX_COMPILER_LAUNCHER` cache
  entries the `ON` branch set with `CACHE STRING`. The configure log and the cache disagree. Since
  that flag is the tool used to prove a rebuild really recompiled, this is a verification-integrity
  bug. Fix: `unset(... CACHE)` in the `else()`.
* **Grepping build logs for `ERROR` matches `WW3D_ERROR_OK`**, which is a *success* line, and invents
  a phantom error on a completely clean boot. Use `\bERROR\b`.

Mac↔iPad determinism is **proven**, not assumed: the `SimulationMathCrc` object's `__text` section is
byte-identical between the two builds, and all 15 libm probe values match bit-for-bit.
`-ffp-contract=off` is on 100% of translation units in both, which matters far more for this
codebase than fdlibm does.

## Windows: how it got here

The first build produced 5,529 errors. Almost all of them were **one family of bug**: Linux/POSIX
compatibility headers shadowing the real Windows SDK, because their directories were on the `-I`
path and the preprocessor searches those before system paths.

    5,529 -> 1,490   scoping CompatLib/Include to d3dx8-only on Windows
    1,490 ->    28   three more shadowing header sets (DXVK's Linux windows.h, WWAudio/mmsystem.h)
       28 ->    22   __int64/_int64 typedefs, module_compat.h, thread ID, C4189
       22 ->     9   ATL/MFC installed on the build machine
                     (win32 stalled here: the last 20 errors were 32-bit-only, see below)
    x64 first build: 155 errors, 73 failing steps, 138 objects

Two traps worth remembering, both of which cost a full rebuild each:

* **The Windows clone must be a pure mirror.** Agents that edited it directly caused `git pull` to
  fail silently, and two rebuilds compiled identical code. Always
  `git fetch && git reset --hard origin/main && git clean -fd`, never `pull`.
* **`grep -c` exits 0 when it finds matches**, so `build && grep -c error && commit` commits on
  failure. Gate on the build script's exit code instead.

## Why 32-bit was abandoned

`GeneralsMD/Code/CompatLib/CMakeLists.txt:6` gates the d3dx8 implementation on
`(WIN32 AND CMAKE_SIZEOF_VOID_P EQUAL 8)`, because 32-bit Windows was expected to link the legacy
DirectX SDK's `d3dx8.lib`, which we do not have. So on win32 that library is skipped and every
`D3DXBUFFER` / `D3DXVec4Dot` / `D3DXMATRIX` symbol is undefined — the last 20 of its 25 errors were
purely an artefact of the architecture.

x64 is required regardless: `BitFlagsIO.h:218` does `xferUser(this, sizeof(this))` under
`RETAIL_COMPATIBLE_CRC` — the pointer, not the object — so a 32-bit peer feeds 4 bytes into the
network CRC where a 64-bit peer feeds 8. A 32-bit Windows build can never hold lockstep with the
Apple builds. 32-bit was scaffolding; it is not a deliverable.

## Windows x64: what is failing now

Four diagnostics at commit `00de2ba91`:

    x41  C1083  Cannot open include file: 'pthread.h'
    x41  C2371  'ULONG': redefinition
    x41  C2371  'DWORD': redefinition
    x32  C1083  Cannot open include file: 'mss.h'   (WWAudio/AudibleSound.h:42)

Established while diagnosing, so do not re-derive:

* `SAGE_USE_DX8 = ON` in the x64 cache and `build/win64/_deps/dxvk-src` **does not exist** — so the
  ULONG/DWORD/pthread errors are *not* DXVK this time (that was the win32 cause, fixed in
  `cmake/dx8.cmake`). Some other include path is pulling in a POSIX compat set. Inspect the actual
  `-I` list of a failing compile rather than guessing.
* `AudibleSound.h:41` is `#if !defined(SAGE_USE_OPENAL)` → `#include "mss.h"`, else `MilesStub.h`.
  **Miles Sound System is 32-bit only** and the root `CMakeLists.txt:63` gate deliberately excludes
  `miles.cmake`/`bink.cmake` at x64, so no `mss.h` exists and none can. macOS avoids this via
  `SAGE_USE_OPENAL`; the x64 Windows answer is almost certainly the same.

## Decisions already made — do not relitigate

* **Windows uses the legacy Win32 device layer** (WinMain/WndProc/Win32Mouse/DirectInputKeyboard);
  SDL3 stays the Apple/Linux arm. `GeneralsMD/Code/Main/CMakeLists.txt:73-78` already selects this,
  so the ~3,550 SDL3 lines were never going to compile on Windows. jmarshall's Win64 port
  (`references/jmarshall-win64-modern`) kept the legacy layer and needed **no** pointer-width fixes
  there — `HWND`/`WPARAM`/`LPARAM` widen for free.
* **No client-side anti-cheat.** GPLv3, players self-compile. Generals Online — the largest live
  server for this codebase — ships zero client integrity checking; their enforcement is a bearer
  token and a server-side ban list. Map hack is unpreventable because lockstep requires every client
  to hold full world state.
* **Do not adopt TheSuperHackers PR #2670 yet.** It is under CHANGES_REQUESTED (OmniBlade,
  2026-07-21) objecting to the exact API surface 82 of our files would adapt to.
* **Generals Online cross-play is unreachable** — they run 60 Hz logic with a 2x frame multiplier
  (`NextGenMP_defines.h:61`) and force all `RETAIL_COMPATIBLE_*` to 0. A GeneralsX peer desyncs at
  frame 1 regardless of network layer.
