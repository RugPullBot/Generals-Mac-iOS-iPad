SHAPE
  50 matches. Each runs the SAME pinned seed as a SOLO headless match on macOS and on Linux with
  no packets exchanged between them, and every frame is diffed. Nothing in the result can be
  explained by the relay, by NAT or by packet loss - which is the point: a networked run conflates
  simulation with transport and cannot say which failed.
  Seeds 700000 + 977n (977 is prime, so seeds do not fall into a pattern). Map and AI spec vary
  per iteration across 10 standard multiplayer maps and Hx1/Mx1/Ex1/Hx2. Every iteration includes
  an AI, because skirmish scripts attach only for AI players and that is where the historical
  divergence lived.

THE BUG THIS RUN FOUND, BEFORE IT COULD PRODUCE A RESULT
  On its first execution the soak failed 100% of iterations on the Linux side while macOS
  simulated its frames perfectly:

      UDP::Bind failed (status -6) for IP 0.0.0.0 port 8086
      [LAN] localIP=10.42.0.1 ... transportInit=FAILED
      GameMain() returned with code 1

  The VPS is also the relay host. With RelayAddress set, the game enters relay mode, relay mode
  forces a wildcard bind, and the game's socket collides with the relay's own listener. This is
  the documented "the relay cannot share a machine with a player" rule, applied everywhere in the
  project except in this script - because the script had never been run, and a script that has
  never run has never had its assumptions tested.

  Fixed in fab389312: the remote peer now runs under `ip netns exec $VPS_NETNS`, the namespace is
  verified to exist in preflight rather than 50 iterations later, and a zero-frame iteration now
  prints the bind error instead of only "no frames simulated" - which had made a setup fault look
  like a headless or determinism bug.
