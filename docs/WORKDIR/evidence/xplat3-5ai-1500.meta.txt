The case neither prior test covered. The 50x1500 soak is macOS vs Linux with ZERO networking.
relay-8peer is eight copies of the same Linux binary. relay-winhost-600 is two peers. This is
Windows x64 + Linux x86-64 + macOS arm64, in the same lobby, over the relay, with five Hard AI
fighting, every frame compared.

=== the control, and why it matters here ===
The FIRST run of this test used killing fields (relay-8peer.sh's default) and produced the same
single md5 across all three platforms - and only 4 distinct CRC values in 1500 frames, 1496 of
them identical. Five Hard AI were placed correctly on that map (aiPlayers=5, sidesWithScripts=7)
and then nothing happened. relay-8peer.meta.txt has the same signature on the same map
(distinct=3). Agreement on an idle simulation is not evidence of determinism, and the harness
fails the run rather than reporting it as a pass. alpine assault is the map that makes the AI act.

=== two bugs this run surfaced ===
1. Windows headless was believed broken and was driven through the GUI with scripted mouse clicks
   in earlier sessions. It was never broken: it needs CNC_GENERALS_ZH_PATH pointing at the Steam
   data install, and without it the engine stalls forever right after
   "[INI] ERROR: No files read from directory". With it set, it reaches SimID in ~5 seconds.
2. The Windows peer reaches its frame limit, logs "simulated N frames", flushes, and THEN faults
   on teardown with 0xC0000005. The frame data is complete and the comparison above is unaffected,
   but the crash is real and is not yet diagnosed.
